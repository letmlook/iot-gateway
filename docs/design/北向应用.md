# 设计文档：北向应用插件（HTTP/Webhook、Kafka、InfluxDB v2、TDengine）

> 功能项：`north-http`（HTTP/Webhook 推送）、`north-kafka`（Kafka 生产）、`north-influxdb`（InfluxDB v2 行协议写入）、`north-tdengine`（TDengine taosAdapter REST 写入）。
> 本文自包含：实现者只需读本文与文中引用的源码文件，无需其他评审材料。所有路径均相对仓库根目录，行号以撰写时的 `main` 分支（commit 17da7cd）为准。

---

## 一、目标与范围

| 功能项 | 目标 | 主要改动面 |
|---|---|---|
| `north-http` | 新北向插件 `plugin-http`：把 GroupData 以可配置格式（复用 plugin-mqtt 的五种上传格式）POST/PUT 到用户 URL，支持 Bearer/Basic 认证、TLS（rustls）、超时、离线缓存与补发 | `gateway/gateway-plugins/plugin-http/`（新增 crate）、`gateway/gateway-plugin-common/`（新增共享 crate，见 §3.2）、`gateway/gateway-server/src/main.rs`、`web/src/views/NorthApps.vue`、`scripts/package-release.sh`（§3.7.4） |
| `north-kafka` | 新北向插件 `plugin-kafka`：把 GroupData 按 topic 模板生产到 Kafka；rdkafka 放在**非默认 feature** 后，默认构建不编译 librdkafka | `gateway/gateway-plugins/plugin-kafka/`（新增 crate）、`Cargo.toml`（workspace 成员）、`scripts/build-plugins*.sh/.ps1/.bat`、`scripts/package-release.sh`（kafka 需独立构建行，§3.7.4） |
| `north-influxdb` | 新北向插件 `plugin-influxdb`：把 GroupData 编码为 InfluxDB 行协议，批量写入 InfluxDB v2 `/api/v2/write`（Token 认证） | `gateway/gateway-plugins/plugin-influxdb/`（新增 crate）、`gateway/gateway-plugin-common/src/line.rs`（共享行协议编码器） |
| `north-tdengine` | 新北向插件 `plugin-tdengine`：通过 taosAdapter REST（`/influxdb/v1/write` 行协议 + `/rest/sql` 建库）写入 TDengine 3.x，复用同一行协议编码器与 HTTP 基建 | `gateway/gateway-plugins/plugin-tdengine/`（新增 crate）、`gateway/gateway-plugin-common/` |

四个插件与 plugin-mqtt 保持**同一套模式**：同一种 ConfigSchema 形态、同一套离线缓存（磁盘持久化 + 满溢丢最旧 + 截断容错 + 压缩）、同一种「on_group_data 只做序列化与入通道/入队（无网络 IO）+ 独立 OS 线程 worker + 指数退避重连/补发」的事件模型（含与 mqtt 一致的「无 client 即丢弃并计数」stub 语义，§2.2/§3.3）、同一组 `connection_status` 返回键。

**不在范围内**（明确排除，防止实现走偏）：

- Kafka **只做生产**，不做消费/订阅反控；InfluxDB/TDengine 只写不查。
- Kafka v1 **不含 TLS/SASL 构建**（`rdkafka` 的 `ssl`/`sasl` 系 feature 不启用，详见 §3.6 的「可选性」）；InfluxDB/TDengine v1 不做 mTLS 双向认证（CA 信任文件支持，客户端证书不做）。
- 不改 `gateway-sdk` 的 trait、FFI ABI 与 `GroupData` 结构；不新增指标体系（复用现有 `DataFlowMetrics` 与 `connection_status` 通道）。
- 不做多租户：按 `docs/design/多租户.md` S18 的结论，北向插件的 topic/URL/队列均按节点隔离，形态 B 下**零改动**；本设计维持「每节点独立配置 + 每节点独立队列文件」的结构以继承该结论。
- 不做上传格式的新协议变体（复用 mqtt 现有五格式：`values_format` / `tags_format` / `ecp_format` / `group_data` / `raw_data`，`plugin-mqtt/src/format.rs:91-212`）。

## 二、现状与衔接点

### 2.1 北向插件机制（SDK 已就绪，本设计不动它）

- `NorthPlugin` trait（`gateway/gateway-sdk/src/plugin.rs:154-209`）：`meta` / `config_schema` / 生命周期 `open→init→start⇄stop→uninit→close` / `setting` / `connection_status` / `set_subscriptions` / `on_group_data`。北向无 `validate_tag`/`poll_group`。
- `connection_status(node_id) -> Option<serde_json::Value>`（`plugin.rs:193-196`）由 API 透出：`GET /api/nodes/:id/connection-status`（路由为**连字符**，`gateway/gateway-server/src/api/mod.rs:279-281`；处理函数 `get_node_connection_status`，`handlers.rs:1181-1187`）。**该通道对所有北向插件通用，新插件零后端 API 改动。**
- `config_schema()` 返回 `ConfigSchema`（`gateway/gateway-sdk/src/schema.rs:99-108`）后，前端按 Schema 自动生成表单（`ParamType`：int/string/bool/file/select，`schema.rs:16-27`；`depends_on`/`depends_values` 条件显隐，`schema.rs:78-86`）；创建与热改配置共用 `validate_config`（`schema.rs:199-299`）。**新插件不需要任何专用前端表单。**
- 敏感参数机制已就绪：`ConfigSchema::sensitive(&[...])` 声明（`schema.rs:126-135`）+ 名称兜底关键词（password/token/secret/access_key 等，`schema.rs:321-343`）→ API 返回脱敏为 `"***"`（`schema.rs:151-161, 318`）、落盘 AES-256-GCM 加密。**新插件的口令/Token 必须命中这套机制**（声明 + 命名遵守关键词）。
- `GroupData` 自带 `node_name` / `group_name` / `tag_names`（`gateway/gateway-sdk/src/messages.rs:8-24`），plugin-mqtt 的格式化已按「名称优先、id 兜底」处理（`format.rs:82-87`），新插件直接复用。

### 2.2 plugin-mqtt 是本设计的参考实现（逐条对应）

- **事件模型**：`open()` 里解析配置 → 创建客户端 → 打开离线队列（`lib.rs:116-170`）→ 用 `std::thread::spawn` 起独立 OS 线程，线程内建 `current_thread` runtime 跑 `run_event_loop`，退出用 oneshot 通道（`lib.rs:184-211`）；`close()` 先压缩队列、再发取消、5s 超时等线程退出（`lib.rs:274-289`）。
- **为什么必须这样**（本设计沿用同一理由，所有实现者不得违反）：
  1. FFI 宏每次调用都新建一个单线程 runtime（`gateway/gateway-sdk/src/ffi.rs:333-341` 南向、`ffi.rs:627-634` 北向的 `__gateway_plugin_block_on`）。若在 `on_group_data` 里内联做网络请求，FFI 模式下每条数据都要新建 runtime + 阻塞整个调用。
  2. Core 的北向消费循环对 `on_group_data` 是**串行 await**（`gateway/gateway-core/src/manager.rs:399-434`，`plugin.on_group_data(id, data).await` 在 `manager.rs:417`）。回调慢会拖住整条消费链路并触发 Lagged（`manager.rs:430-433`）。mqtt 的 `on_group_data` 只做：读连接状态 → 已连接则 `client.publish`（channel send，O(1)）→ 失败则入离线队列（`lib.rs:348-404`）。
- **重连退避**：1s 起指数翻倍、上限 30s、连上复位（`lib.rs:455-457, 534-535`）；连接成功后按 `cache_sync_interval_ms` 节拍补发离线队列，失败记录 `push_front` 放回队首保序（`lib.rs:484-516`）。
- **离线队列**（`plugin-mqtt/src/queue.rs`）：记录格式 `[u32 LE topic 长度][topic][u32 LE payload 长度][payload]`（`queue.rs:17-19`）；满溢丢最旧并计数（`queue.rs:179-186`）；重启按序恢复、截断尾巴容错（`queue.rs:128-176`）；已消费过半压缩（`queue.rs:266-300`）；磁盘不可用降级纯内存（`queue.rs:237-243, 258-262`）。**自带 9 个单测**（`queue.rs:309-489`）。
- **配置辅助**：`config_str/u16/usize/bool`（`config.rs:28-54`）与默认值常量（`config.rs:8-26`，如 `DEFAULT_CACHE_MEMORY_SIZE=1000`、`DEFAULT_CACHE_DIR="data/mqtt-queue"`、`DEFAULT_CACHE_SYNC_INTERVAL_MS=100`）。
- **无客户端编译分支**（注意：其语义是**丢弃**，不是入队）：`#[cfg(not(feature = "mqtt-client"))]` 时 `open()` 只建状态与空队列（`lib.rs:228-246`），而 `on_group_data` 对消息**既不发送也不入队**，直接丢弃并打日志（`lib.rs:396-401`：`let _ = (topic, payload); tracing::info!(… "mqtt (no client): would publish")`）；`connection_status` 仍返回（空的）队列统计。即参考实现的 stub 不承担缓存职责。本设计沿用「丢弃 + 计数」的 stub 语义并在新插件上加可观测计数（§3.3）。

### 2.3 注册与构建衔接

- 静态注册：`main.rs` 的 `register_builtin_plugins()` 目前只注册 sim/modbus-tcp/modbus-rtu/mqtt（`gateway/gateway-server/src/main.rs:55-64`）；**只有当 `plugins_dir` 不存在/为空/加载失败时才回退内置**（`main.rs:69-109`），静态与 .so 部署互斥，维持现状。
- feature 先例：`plugin-opcua` 的重客户端依赖放非默认 feature（`plugin-opcua/Cargo.toml`：`default = []`，`opcua-client = ["dep:opcua"]`，注释注明需要系统 OpenSSL）；`plugin-mqtt` 的 `default = ["mqtt-client"]`、`ffi = []`。
- CI（`.github/workflows/ci.yml`）：`cargo check --workspace --all-targets`、`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --check`，**全部只开 default feature**。因此：默认 feature 必须能在 ubuntu-latest 上无外部 C 依赖编译通过——这是 plugin-kafka 的 rdkafka 必须放非默认 feature 的直接依据。
- 构建脚本有**两套**，都必须改（只改联调脚本会让新插件在发布形态缺席）：
  - 日常联调：`scripts/build-plugins.ps1` / `build-plugins.bat` / `build-plugins-so.sh`，逐插件 build + 拷贝；
  - **发布包**：`scripts/package-release.sh` —— 40-43 行以 `--features ffi` 显式枚举构建 `plugin-sim/-mqtt/-modbus-tcp/-modbus-rtu/-opcua/-virb`，60-63 行 `for p in sim mqtt modbus_tcp modbus_rtu opcua virb` 把 `libplugin_*` 复制进包内 `plugins/`。发布包必然带非空 `plugins/`，而 `main.rs:69-109` 的内置回退只在 plugins 目录缺失/为空/加载失败时触发——**新增插件不进这两个列表，release 部署（动态加载模式）里就彻底不可用**。
- docker-compose.yml 已有「北向联调对象」先例（mosquitto 服务，注释写明用途），四个新插件的真机验证沿用该文件扩展。

### 2.4 当前不存在的能力（本设计要补的空缺）

- 仓库当前**没有任何 HTTP 客户端依赖**：`Cargo.lock` 分析（2026-10-05；`grep -c '\[\[package\]\]' Cargo.lock` = 318，`grep -c '^name = '` = 318，二口径一致）无 `reqwest`、无 `rdkafka`、无 `taos`；`hyper 1.8.1` 仅由 axum 服务端引入，不能直接当客户端 API 用。
- 北向插件仅 `plugin-mqtt` 一个；`docs/功能实现清单.md` §三 明确「HTTP / Webhook 北向 🚧 C2」「Kafka / InfluxDB / TDengine 北向 🚧 C2（旧清单误标为已实现）」——本设计即 C2 的落地。
- 前端 `web/src/views/NorthApps.vue:62-71` 对连接徽章做了 `row.plugin_name === 'mqtt'` 的硬编码特判（`NorthApps.vue:249-250` 另有 last_error 提示）；`web/src/components/DeviceCard.vue:75-77` 的徽章渲染本身已是通用的 `connection_status.connected === false` 判断。需要把 NorthApps 的特判通用化（§3.7）。

## 三、方案

### 3.1 依赖选型及理由（已实际核实，2026-10-05 执行）

| crate | 核实命令与结果 | 结论 |
|---|---|---|
| `reqwest` | `cargo info reqwest` → `0.13.5 (rust-version: 1.85.0)`；`cargo info reqwest@0.12.24` → `0.12.24 (rust-version: 1.64.0)`；crates.io API 取完整 feature 表：`rustls-tls = [rustls-tls-webpki-roots]`、`rustls-tls-webpki-roots = [... + __rustls-ring]`、`json = [dep:serde_json]` | **采用 `reqwest 0.12`，`default-features = false, features = ["json", "rustls-tls"]`**。TLS 走 rustls + **ring** 提供方（已核实 feature 链），webpki 根证书随包内置。拒绝 0.13（新 major，默认 TLS 提供方语义有变，等生态稳定后再单独评估）。本机工具链 `rustc 1.99.0`（实测）满足 MSRV |
| ring（reqwest 传递依赖） | ring 仓库 `BUILDING.md`（GitHub API 抓取，默认分支）明确：「The *ring* crate released on crates.io … for Windows x86 and x86-64, the packaged crate contains precompiled object files … so no macro assembler」 | **crates.io 打包版 ring 在 Windows MSVC 只需 C 工具链**，无需 NASM/Perl/CMake/OpenSSL。这是 HTTP 系插件可以进 default feature 的依据 |
| `rdkafka` | `cargo info rdkafka` → `0.39.0 (rust-version 1.74)`，features：`default=[libz,tokio]`、`cmake-build`、`ssl`、`ssl-vendored`、`sasl`、`zstd`、`dynamic-linking`；`rdkafka-sys 4.10.0+2.12.1`（librdkafka 2.12.1） | **采用 `rdkafka 0.39`，放在非默认 feature `kafka-client` 后**。构建要求已核实（rdkafka-sys `build.rs`，GitHub API）：不带 `cmake-build` 时走 configure/make（POSIX only，Windows 不可用）；**Windows 必须开 `rdkafka/cmake-build` 且本机装 CMake**。TLS/SASL 需要额外系统依赖（openssl / cyrus-sasl），v1 不启用 |
| `influxdb`（社区客户端） | `cargo info influxdb` → `0.8.0` 存在，底层就是 reqwest | **存在但拒绝采用**：其 API 面向「单点 WriteQuery + 类型化字段」，不适合网关的高吞吐行协议批量写；行协议本身是稳定文本格式（官方语法已核实，见下），自研编码器约 100 行、可完全单测。少一个依赖层，且编码器可与 plugin-tdengine 共用 |
| `taos`（TDengine 官方连接器） | `cargo info taos` → `0.12.3`，`default=[ws-rustls, optin, deadpool]`（纯 Rust WebSocket，taos-query/taos-ws 多 crate 栈） | **存在但 v1 拒绝采用**：引入整条 taos-query/taos-ws/deadpool 依赖链，而本需求只有「写入」，用 taosAdapter 的 HTTP 行协议接口（reqwest 已覆盖）即可。留作后续需要订阅/流查询时的备选 |
| 行协议语法 | 官方文档 docs.influxdata.com/influxdb/v2/reference/syntax/line-protocol/（WebFetch 全文核实）：measurement 逗号空格转义；tag key/value 与 field key 逗号等号空格转义；字符串 field 双引号+反斜杠转义；整型 `i` 后缀、无符号 `u` 后缀、布尔 `t`/`f`、浮点默认；同 measurement+tag set+timestamp 重复提交合并字段、新值胜出 | 编码器实现与单测按此口径（§4.1） |
| InfluxDB v2 写端点 | `POST {url}/api/v2/write?org=&bucket=&precision=` + `Authorization: Token <token>` + `Content-Type: text/plain; charset=utf-8`，成功 204（docs.influxdata.com InfluxDB v2 Write data / HTTP API；精确状态码与 header 细节在真机项二次确认，§4.2） | plugin-influxdb 的请求构造依据 |
| TDengine taosAdapter | taosadapter 源码（GitHub API，ref `3.3.6` 与 `3.4.0`）核实：`POST /rest/sql`、`/rest/sql/:db`（Basic auth）；influxdb 插件 `String()="influxdb"` + `Version()="v1"` → 路由组 `influxdb/v1`，注册 `POST write`，参数 `db`（必填）、`precision`（默认 ns）、`u`/`p` 或 Basic auth、`table_name_key`（指定子表名的 tag），成功 **204**；官方文档（docs.taosdata.com 3.4.3 组件页，WebFetch 核实）同样只列 `/influxdb/v1/write`，**明确没有 `/influxdb/v2/write`**，且「不支持 token 验证，仅支持 Basic 验证和查询参数验证」；默认端口 6041 | plugin-tdengine 走 `POST /influxdb/v1/write?db=<库>&precision=ms` + Basic auth；`/rest/sql` 执行 `CREATE DATABASE IF NOT EXISTS`。**网上资料常写的 `/influxdb/v2/write` 在 taosadapter 3.3.6/3.4.0 源码中不存在，禁止使用** |

共享依赖（已在 workspace 锁文件中，不新增）：`serde`/`serde_json`、`chrono`、`uuid`、`tokio`、`async-trait`、`tracing`、`thiserror`（SDK 侧），与 plugin-mqtt 的依赖面一致（`plugin-mqtt/Cargo.toml`）。

### 3.2 公共前置：新共享 crate `gateway-plugin-common`

四个插件 + plugin-mqtt 需要同一批基础设施。为避免把 mqtt 最精微的队列代码复制四份造成漂移，新建 workspace 成员 `gateway/gateway-plugin-common/`，plugin-mqtt **同步切换**到它（平移不改行为，以其既有单测为回归门禁）：

```
gateway/gateway-plugin-common/
├── Cargo.toml        # default = []；http = ["dep:reqwest", "dep:serde_json"]（reqwest 配置同 §3.1）
└── src/
    ├── lib.rs
    ├── config.rs     # 自 plugin-mqtt/src/config.rs:28-54 平移 config_str/u16/usize/bool（补 u64）；
    │                 # 公共默认常量：DEFAULT_CACHE_MEMORY_SIZE=1000、DEFAULT_CACHE_SYNC_INTERVAL_MS=100、
    │                 # DEFAULT_CACHE_PERSIST=true（源自 config.rs:11,14,16 与 lib.rs:116 的默认值）
    ├── queue.rs      # 自 plugin-mqtt/src/queue.rs 全文平移：Record{topic,payload}/QueueStats/OfflineQueue
    │                 # + 9 个单测原样随迁（断言不改）。topic 字段语义放宽为「路由说明（用于日志/观测）」：
    │                 # mqtt/kafka=主题；http=URL 路径；行协议插件填空串。二进制格式与 API 完全不变
    ├── format.rs     # 自 plugin-mqtt/src/format.rs 平移：topic_from_template、data_value_to_json_scalar、
    │                 # data_value_ecp_type、data_value_to_number_array、tag_key、payload_for_format、
    │                 # UPLOAD_FORMAT_* 五个常量
    ├── line.rs       # 新增：InfluxDB 行协议编码器（influxdb/tdengine 共用，见 §3.4/§3.5）
    └── http.rs       # feature="http" 才编译：reqwest Client 构造（timeout_ms / insecure_skip_verify /
                      # ca_file / User-Agent "iot-gateway-north/<plugin>"）与 send_and_classify() 状态码分类
```

要点：

- **feature 门控的真实语义**（重要：cargo 的 feature 在整个构建图内按包统一，不存在「按依赖边隔离」一说）：cfg 门控保证的是 **plugin-mqtt 自身代码不引用 `common::http` 模块、不执行任何 reqwest 代码路径**；而在静态链接（gateway 二进制）或 `cargo build --workspace` 下，plugin-http 启用的 `gateway-plugin-common/http` feature 会让同一份 gateway-plugin-common rlib 连同 reqwest 一起编译进最终产物——代价仅是二进制体积，无行为影响（http 模块内的所有条目都带 `#[cfg(feature = "http")]`，mqtt 代码路径不可达）。真正不含 reqwest 的场景只有单独构建 mqtt 的 .so：`cargo build -p plugin-mqtt --features ffi` 的构建图中没有 `http` 边，reqwest 不参与编译。
- `line.rs` 的形状：

  ```rust
  pub struct LinePoint {
      pub measurement: String,                 // 已按模板渲染，转义在 encode 内做
      pub tags: Vec<(String, String)>,
      pub fields: Vec<(String, LineField)>,
      pub ts_ms: i64,
  }
  pub enum LineField { Int(i64), UInt(u64), Float(f64), Bool(bool), Str(String) }
  pub fn data_value_to_line_field(v: &DataValue) -> Option<LineField>;
  // Int8..Int64→Int；UInt8..UInt64→UInt；Float32/64→Float；Bool→Bool；String→Str；
  // Bytes→None（调用方跳过并计数，日志可见）
  pub fn encode(p: &LinePoint, out: &mut String); // 追加一行，含全部转义与 i/u/t/f 后缀
  ```

  转义规则严格按官方语法（§3.1 表格已核实）：measurement 只转义 `,` 与空格；tag key/value、field key 转义 `,` `=` 空格；字符串 field 转义 `"` 与 `\`。`encode` 为纯函数，逐规则单测。
- **plugin-mqtt 迁移的回退口径**：这一步是独立提交，只做「删内部模块 + 换 use 路径」；`cargo test -p plugin-mqtt -p gateway-plugin-common` 全绿才算过。出现无法平移的行为差异时，回退该提交并改为各插件自带副本（代价是四份拷贝，但不阻塞功能项）。

### 3.3 `north-http`：plugin-http

**运行模型**（四个插件的标准模板，后续插件只描述差异）：

```
on_group_data(node_id, data)                     # manager.rs:417 串行调用，必须 O(1)
  → 按 upload_format 序列化 payload（复用 common::format::payload_for_format）
  → Healthy 时 mpsc::try_send(Record)；通道满 → offline_queue.push()（满溢丢最旧，计数可见）
  → 未 open：warn 并跳过（同 mqtt lib.rs:350-356）；Degraded：一律 offline_queue.push()

worker 线程（std::thread + current_thread runtime，oneshot 取消；仿 mqtt lib.rs:193-211）
  Healthy：recv 一条 → HTTP 发送（timeout_ms 超时）
      2xx                    → 继续
      408/425/429/5xx/超时/连接错误 → offline_queue.push(rec)，进 Degraded（backoff=1s）
      其他 4xx               → dropped_rejected += 1，warn（body 前 200 字节），继续
  Degraded：select! { cancel | recv→offline_queue.push(rec) | sleep(backoff) →
      offline_queue.pop_front() → None 则回 Healthy；
      Some(rec) → 发送：2xx → sleep(cache_sync_interval_ms) 继续补发，backoff 复位 1s；
                  可重试失败 → push_front(rec)（保序），backoff = min(backoff*2, 30s)；
                  其他 4xx → 计数丢弃 }
close()：compact_now()（仿 mqtt lib.rs:274-277）→ cancel → join（5s 超时）
```

**ConfigSchema**（全部走 §2.1 的自动表单/校验/脱敏机制；`url` 用 `ParamValid.regex = ^https?://.+` 校验）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `url` | string, Required | —（regex 强制 http(s)） | 推送目标，含路径 |
| `method` | select | `POST` | POST / PUT |
| `content_type` | string | `application/json` | 请求体类型 |
| `auth_type` | select | `none` | none / bearer / basic |
| `auth_token` | string, sensitive | — | bearer 时为 token；basic 时为 `user:password`（名称含 token，自动命中脱敏） |
| `headers_json` | string | — | 额外请求头，JSON 对象如 `{"X-Tenant":"a"}`；`open()` 时解析，失败返回 `ConfigInvalid` |
| `timeout_ms` | int | 5000 | 单请求超时（1–600000） |
| `insecure_skip_verify` | bool | false | 自签名 HTTPS 场景 |
| `ca_file` | file | — | 自定义 CA（reqwest `add_root_certificate`） |
| `upload_format` | select | `values_format` | 五格式同 mqtt（`format.rs` 平移后选项一致） |
| `cache_memory_size` / `cache_persist` / `cache_dir` / `cache_sync_interval_ms` | 同 mqtt | 1000 / true / `data/http-queue` / 100 | 离线缓存四件套，语义与默认值对齐 `config.rs:11-16, 240-291` |

- 请求体：`payload_for_format` 的五格式 JSON 直接作为 body；node/group 信息在 body 内（不拼 URL），URL 模板不做（YAGNI，后续可加）。
- `connection_status` 返回：`connected` / `last_error` / `queue_len` / `queue_dropped_overflow` / `queue_recovered` / `queue_dropped_corrupt` / `queue_persisted`（与 mqtt `lib.rs:331-346` 同键）+ 新增 `dropped_rejected`。
- feature：`default = ["http-client"]`，`http-client = ["dep:gateway-plugin-common/http"]`（对齐 mqtt 的 `default = ["mqtt-client"]`）。**无 client 分支的 stub 语义（与 mqtt 对齐，四插件统一）**：`open()` 只建状态不建 client；`on_group_data` 丢弃数据并打 info 日志 + `dropped_no_client` 计数（**不做离线入队**——stub 下永远无人消费，入队只会静默写满磁盘，这正是 mqtt 参考实现选择丢弃的原因）；`connection_status` 返回 `connected:false` 与空队列统计。
- 静态注册进 `register_builtin_plugins()`（main.rs:63 旁新增一行）。

### 3.4 `north-influxdb`：plugin-influxdb

- **请求**：`POST {url}/api/v2/write?org=<org>&bucket=<bucket>&precision=<ms|ns>`，Header `Authorization: Token <token>`（token 声明 sensitive）、`Content-Type: text/plain; charset=utf-8`；成功 2xx（204）。
- **行协议编码**（`common::line`）：每个 GroupData 一行：
  - measurement = `measurement_template` 渲染（变量同 `topic_from_template`：`${node_id}/${group_id}/${node_name}/${group_name}/${timestamp}`，`format.rs:12-31`），默认 `${node_name}`；
  - tags：`node=<node_name>`、`group=<group_name>`（名称优先 id 兜底）+ `tags_json` 配置追加静态标签（JSON 对象，open 时校验）；
  - fields：每个点位一条 `tag_key(data,id)` → `data_value_to_line_field`（Bytes 跳过并计 `skipped_bytes_fields`，debug 日志）；
  - timestamp：`data.ts.timestamp_millis()`（precision=ns 时用 `timestamp_nanos_opt()`）。
- **批量**：Degraded 补发与健康时的 worker 内微批：攒满 `batch_max_lines`（默认 500）或等 `batch_interval_ms`（默认 200，0=逐条）后一次 POST（多行 `\n` 连接）。行协议天生支持多行单请求。
- **失败分类**：429/5xx/超时/连接错误 → 离线队列（可重试）；400（语法/字段错误）→ `dropped_rejected` 计数丢弃并 warn——重试无法修复坏行。
- **不代管 org/bucket**：v1 不做自动建 bucket（需要 operator token，越权面大）；400 且错误信息含 bucket/org 未找到时，`last_error` 给出明确指引。
- ConfigSchema（差异项）：`url`（默认 `http://127.0.0.1:8086`）、`org`（Required）、`bucket`（Required）、`token`（string, Required, sensitive）、`precision`（select ms/ns，默认 ms）、`measurement_template`、`tags_json`、`batch_max_lines`、`batch_interval_ms` + 缓存四件套（`cache_dir` 默认 `data/influxdb-queue`）+ `insecure_skip_verify`/`ca_file`。
- feature/注册：`default = ["http-client"]`，进 builtin 注册。

### 3.5 `north-tdengine`：plugin-tdengine

与 plugin-influxdb 共用 `common::line` 编码器与 `common::http` 分类器，差异如下：

- **端点**（§3.1 已核实源码）：
  - 写入：`POST {url}/influxdb/v1/write?db=<database>&precision=ms&table_name_key=<table_name_key>`，Header `Authorization: Basic base64(user:password)`；成功 **204**。
  - 建库：`POST {url}/rest/sql`，body `CREATE DATABASE IF NOT EXISTS <db> PRECISION 'ms'`，Basic auth，响应 JSON `code==0` 视为成功。
- **自动建库**：`auto_create_db`（bool，默认 true）。`open()` 时执行一次建库 SQL；失败只 warn 不阻塞（taosAdapter 可能晚于网关启动）；写入收到「database not exist」类错误（4xx）时重试一次建库再写一次，仍失败才丢弃计数。
- **数据库名白名单**：`database` 必须匹配 `^[A-Za-z0-9_]{1,192}$`（Schema regex + `open()` 双重校验），拼接进 SQL 前绝不接受其他字符（防注入）。
- **子表命名**：taosAdapter 默认给行协议写入生成随机子表名（官方文档说明可用 `table_name_key` 指定 tag）。插件给每行注入合成 tag `gateway_table=<node>_<group>`（值做 `[A-Za-z0-9_]` 清洗），`table_name_key` 默认 `gateway_table`，使子表按「节点_组」命名、查询可用；置空则回退 taosAdapter 默认命名。
- **版本探活**：`open()` 时顺带 `POST /rest/sql` 执行 `SELECT server_version()`，把版本号写进节点日志（便于排障；taosAdapter 6041 端口、Basic auth 行为已按 3.3.6/3.4.0 源码与 3.4.3 文档核实）。
- ConfigSchema（差异项）：`url`（默认 `http://127.0.0.1:6041`）、`database`（Required，regex 白名单）、`username`（默认 `root`）、`password`（默认 `taosdata`，sensitive）、`measurement_template`、`tags_json`、`table_name_key`、`auto_create_db`、`batch_max_lines`/`batch_interval_ms` + 缓存四件套（`cache_dir` 默认 `data/tdengine-queue`）。
- feature/注册：`default = ["http-client"]`，进 builtin 注册。

### 3.6 `north-kafka`：plugin-kafka（依赖重，可选性与回退是本节核心）

**可选性设计**（rdkafka 是全仓唯一的 C 库级重依赖）：

```toml
[features]
default = []                       # 仿 plugin-opcua：CI 与常规构建不编译 librdkafka
kafka-client = ["dep:rdkafka", "rdkafka/cmake-build", "rdkafka/libz-static"]
ffi = []

[dependencies]
rdkafka = { version = "0.39", default-features = false, features = ["tokio"], optional = true }
```

- `rdkafka/cmake-build` 对 Windows 是**必需**（rdkafka-sys build.rs 已核实：非 cmake 路径是 configure/make，Windows 不可用）；对 Linux 用 cmake 也无害且行为一致，故固定放进 feature。
- `libz-static` 避免 Windows 运行期 zlib DLL 依赖。
- **不启用** `ssl`/`ssl-vendored`/`sasl`/`zstd`：v1 构建 = 明文 + 无压缩外置依赖（`compression.codec=gzip` 由 librdkafka 内置 libz 支持，可用；`zstd`/`lz4` 配置了会启动失败，错误信息要写明需要加哪个 feature）。
- 部署形态：**不进 `register_builtin_plugins()`**（理由：default 无 client 的 stub 进管理台会让用户创建「永远不发数据的 Kafka 节点」，比 opcua 的 .so-only 模式更差）；只能以 `cargo build -p plugin-kafka --features "ffi,kafka-client"` 出 .so/.dll，放进 `plugins_dir` 加载。`scripts/package-release.sh` 为 kafka 设独立构建行与条件复制（§3.7.4）；构建脚本与文档同步写明 Windows 需要 CMake + VS Build Tools。
- **回退路径**：若某环境 C 库构建失败，可用 `rdkafka/dynamic-linking` 链接系统 librdkafka（apt/yum 装 librdkafka-dev）——仅文档化，不进默认 feature。

**运行模型**（同 §3.3 模板，差异点）：

- `ClientConfig`：`bootstrap.servers` = `brokers`（逗号分隔）；`message.timeout.ms` = `message_timeout_ms`（默认 300000）；`statistics.interval.ms` = `stats_interval_ms`（默认 5000）；`compression.codec`、`acks`；`extra_config_json` 透传任意 librdkafka 属性（open 时 parse + set，set 失败返回 `ConfigInvalid`）。这是无 ssl/sasl 构建下用户配置 `security.protocol=sasl_ssl` 的**显式报错出口**（rdkafka 创建 producer 返回参数错误，原样进 `last_error` 与日志）。
- 发送：`FutureProducer::send(FutureRecord { key = topic 模板渲染值, payload }, Timeout::After(message_timeout_ms))`。
  - `Err(KafkaError, _)`（内部队列满/超时）→ 离线队列，进 Degraded（同模板）；
  - `Ok(fut)` → worker 内 `tokio::spawn` 等待 delivery：成功计数；最终失败（librdkafka 已内部重试耗尽）→ `dropped_delivery` 计数 + warn，**不回灌离线队列**（避免乱序与重复风暴；该取舍写进代码注释与文档）。
- topic 模板：`topic_template` 默认 `gateway/data/${node_id}/${group_id}`（变量同 mqtt，`format.rs:12-31`）；payload 默认 `values_format`（五格式同 §3.3）。
- 连接状态：实现 `ClientContext::stats()` 回调（`statistics.interval.ms` 周期触发），解析 stats JSON 中 `brokers` 的 `state == "UP"` 置 `connected`——无数据流量时状态也准确。`connection_status` 返回键与 §3.3 一致。
- 无 client（`not(feature = "kafka-client")`）：stub 语义同 §3.3（丢弃 + `dropped_no_client` 计数 + `connected:false`，不入队），CI 可测。
- ConfigSchema：`brokers`（Required，regex 非空逗号分隔 host:port）、`topic_template`、`acks`（select 0/1/all，默认 1）、`compression`（select none/gzip，默认 none）、`message_timeout_ms`、`stats_interval_ms`、`extra_config_json` + 缓存四件套（`cache_dir` 默认 `data/kafka-queue`）+ `upload_format`。

- 离线队列「重启不丢」已在 mqtt 实测过（功能清单 §三），四个新插件复用同一实现，单测 + http/tdengine 各一次真机重启验证即可，无需四份完整断网剧本。
- librdkafka 内部缓冲与我们离线队列的**交接时序**（何时开始丢到外部队列）只能真机观察，单测无法覆盖。
- InfluxDB 2.x 写端点的精确请求形状（§3.1 表）以 4.2 真机为准，若有出入以真机实测修正 `http.rs` 构造。
- 性能基线不在本设计范围；如需，可仿 `gateway-bench` 先例后续加 FFI JSON 往返 + 序列化基准。

## 五、风险与回退

| # | 风险 | 缓解 / 回退 |
|---|---|---|
| R1 | **librdkafka 构建失败**（Windows 缺 CMake/MSVC；Linux 缺 make/gcc） | 已隔离到非默认 feature，CI 与其他三项完全不受影响；构建要求写进脚本注释与 CLAUDE.md；最后回退 `dynamic-linking` + 系统包。kafka 是四项中唯一可能延期项，不阻塞其余三项 |
| R2 | taosAdapter 版本差异（3.0–3.4 端点/参数变化） | 端点已按 3.3.6/3.4.0 源码 + 3.4.3 文档双核实；`open()` 打印 `server_version()`；真机项做端点回归。低于 3.0 的版本明确不支持（文档写明） |
| R3 | `/influxdb/v2/write` 网传端点误用 | 已核实 taosadapter 源码无此路由；实现只允许 `/influxdb/v1/write`（代码注释引用本节） |
| R4 | InfluxDB 行协议注入/坏行 | 编码器集中转义 + 逐规则单测；db 名白名单；400 一律丢弃计数不重试（不污染队列） |
| R5 | 同 measurement+tags+timestamp 的点互相覆盖（官方合并语义） | GroupData 间隔 = 组 interval（下限 10ms）远大于 ms 精度；确需亚毫秒的场景用 `precision=ns`；风险写进配置描述 |
| R6 | 离线队列磁盘放大 | 沿用 MAX_RECORD_BYTES=8MB 上限、满溢丢最旧、过半压缩、磁盘故障降级内存（queue.rs 全套机制平移） |
| R7 | `on_group_data` 被实现成慢回调导致 Lagged | §2.2 的两条理由写进模板注释；评审检查点：`on_group_data` 内不允许出现 await 网络 IO |
| R8 | plugin-mqtt 迁移引入回归 | 迁移是独立第一步，只平移不改断言，`cargo test -p plugin-mqtt -p gateway-plugin-common` 门禁；异常即回退该提交改走复制路线 |

## 六、分步实施顺序

按依赖与风险排序，每步可独立编译、测试、提交；每步完成后跑 `cargo test`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all -- --check`（CI 已强制）。

1. **【公共前置①】`gateway-plugin-common` 抽取 + plugin-mqtt 切换**：crate 骨架、queue/format/config 平移（含 9 个队列单测）、plugin-mqtt 换依赖并删除内部模块、加入 workspace。门禁：`cargo test -p plugin-mqtt -p gateway-plugin-common` 全绿；不对行为做任何修改。
2. **【公共前置②】`common/line.rs` 与 `common/http.rs`**：行协议编码器 + reqwest Client 构造与状态码分类（feature `http`），连同 §4.1 的编码/分类单测。此步完成后 north-http/influxdb/tdengine 只剩装配工作。
3. **【north-http①】插件主体**：worker 状态机（§3.3 模板）、ConfigSchema、stub 分支、`connection_status`；mock server 单测全绿。
4. **【north-http②】接线**：workspace 成员、`register_builtin_plugins()` 增 http、`NorthApps.vue` 徽章通用化、`build-plugins*` 三脚本增行。真机：§4.2 http 行（断网恢复 + 4xx 丢弃）。
5. **【north-influxdb】插件 + 真机**：行协议装配（measurement 模板/tags/批量）、org/bucket/token 配置、批量与失败分类；mock server 单测；真机 §4.2 influxdb 行。
6. **【north-tdengine】插件 + 真机**：复用行协议 + `/influxdb/v1/write`、建库与白名单、`table_name_key` 合成 tag、版本探活；单测；真机 §4.2 tdengine 行（含端点回归记录）。
7. **【north-kafka①】stub 与 Schema（进 CI）**：default feature 下的 stub、ConfigSchema、brokers/extra_config 校验、stats 解析纯函数单测。
8. **【north-kafka②】kafka-client 实现（不进 CI）**：FutureProducer worker、delivery 计数、stats 回调连通性；Linux 容器真机（§4.2 kafka 行）；Windows `--features "ffi,kafka-client"` 构建走通一次并记录 CMake 要求；`scripts/package-release.sh` 的 kafka 独立构建行（含无 CMake 容错跳过）与条件复制落地验证；.so 部署验证（不进 builtin）。
9. **【收尾】**：`scripts/package-release.sh` 全流程跑通一次并抽查包内 `plugins/` 含全部新插件（kafka 视发布机 CMake 而定）；docker-compose 增加 influxdb/tdengine/kafka 可选服务段；CLAUDE.md feature 表补四行；`docs/功能实现清单.md` §三 C2 两行更新为 ✅ 并附四条真机验证记录。

> 实施顺序的可裁剪性：第 5、6、7+8 步互相独立，可并行/按需取舍；kafka 全部延期的极端情况下，第 1–6 步交付的三个插件不受任何影响（common crate 不含 rdkafka）。
