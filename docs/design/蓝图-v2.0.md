## 2. v2.0 主题规划

> 量级口径：S ≤ 3 人日，M 3–8，L 8–15，XL > 15。均含测试与文档；门禁沿用
> fmt / clippy -D warnings / cargo test --workspace / 前端 build。

### T1 流程编排与告警引擎 v2 ⭐ 主线（Q1 已拍板；XL，20–30 人日 MVP）

> **进度（2026-11-08）**：T1-① 设计稿 → **T1-② 引擎 crate**（8 单测）→ **T1-③ FlowStore + CRUD**
>（gateway-server 140 测试全绿）→ **T1-④ 运行时接线 + 告警子系统**（闭环集成测试）→
> **T1 前端落地**（VueFlow 编辑器 + 流程列表 + 告警中心 + graphMapping 7 项往返测试）→
> **M1 收尾完成**（WS alarm 帧 + 优雅停机 stop_all + 真机验收清单，实施报告 §7）→
> **真机端到端验收通过（2026-11-21，实施报告 §8）**：§7.1 清单 10 步全过，过程中发现并
> 修复 5 项缺陷（Pinia 迁移孤儿 inject、structuredClone 克隆 reactive、operators 未声明
> sink 类别致 UI 无法发布、WS auth 裸 token 全拒、错误细节被翻译吞掉）+ 1 项测试基建
> 修复（全局 WS 计数测试串行化）。**M1 出口条件达成**；Q4（license 特性位）待授权侧拍板。

- **目标**：数据面可编排——源（南向采集/历史/手动）→ 处理（规则/过滤/聚合/脚本）→ 汇（北向/告警/存储）以 DAG 声明并可视化编辑；告警从「规则命中即发」升级为生命周期（产生/确认/恢复/升级）。
- **现状差距**：规则引擎 + filters 是单点流水线，无多级编排；无告警生命周期与告警中心页。
- **关键资产**：`redesign/v1-flow-orchestration` 分支（66 commits，+38.8k 行，2026-01~05）含 FlowEditor、flow 节点/边持久化、告警事件页的完整探索——**作为设计参考在当前 main 上增量重做**（该分支早于多租户/Review 加固，直接 graft 风险高，见 §6）。
- **范围切分（MVP→完整）**：① flow 数据模型 + 执行引擎（复用 bus/filters/rules 原语）→ ② 告警事件表 + 生命周期 API → ③ FlowEditor 前端重做（按需引入后 components.d.ts 体系内）→ ④ 告警中心页 + 通知渠道（复用北向插件）。

### T2 历史数据前端化（S–M，3–6 人日）—— ✅ 已完成（2026-11-08，M1 批次一）

- **目标**：补齐「后端已就绪、前端为零」的断层——历史曲线页（多点位叠加、时间范围、降采样展示）、历史报表导出。
- **现状差距**：`/history/series` 等三个 API 已实现（含租户过滤、分桶查询），前端无任何调用。
- **结果**：曲线页已落地（ECharts 按需、独立懒加载 chunk；序列多选 + 时间范围 + min/max 置信带；未启用态指引）；**执行过程中计划外发现并修复管理台 P0**（前端 BASE 与后端 v1 别名契约不匹配，登录等大部分请求自 `887d387` 起 404，详见 `docs/实施报告-v2.0.md` §1.2）；报表导出顺延至后续批次。

### T3 API v2（M，5–8 人日）

- **目标**：`/api/v2/` 版本化；列表类端点分页；写路径速率限制；OpenAPI-first codegen 扩展到全部端点。
- **现状差距**：路由级 OpenAPI 注解已有，但无版本化/分页/限流；契约类型仅部分生成。
- **约束**：v1 路径保留一个兼容期（时长见 §7 Q4），WS 协议同步升版。
- **进度（2026-11-21，M2 批次一）**：✅ 版本化（`/api/v2` 显式别名与 v1 分页策略同构，RBAC/审计/限流按归一化路径同语义）+ ✅ 列表分页（v1 起已就位）+ ✅ 写路径限流（固定窗口，身份/IP 维度，429 + Retry-After，env 可配可关）。
- **进度（2026-11-22，M2 收尾）**：✅ OpenAPI-first codegen 全量（flows/alarms 桩 T1 起已全；本批补 WS alarm 帧契约与 info/tags 声明，`gen:api` 重新生成前端类型）；✅ WS 升版评估——**结论：无需断裂升版**（帧新增向后兼容、auth 双形态兼容、hello.version 可探测、Close(4002) 已有），结论写入 OpenAPI info.description。✅ M2 真机验收通过（实施报告 §11.3）。**T3 完成。**

### T4 运维与交付（M，5–8 人日）

- **目标**：容器镜像进 Release（当前 release.yml 只出 tar+SHA256SUMS）；`data.db` schema v2→v3 升级向导（就地迁移 + 回滚点）；nightly bench 自动与最近基线对比、越界告警。
- **现状差距**：镜像未发布；升级仅靠启动迁移；bench nightly 存档但不做对比判定。
- **进度（2026-11-22，M3）**：✅ 容器镜像接线——Dockerfile workspace 清单补全 9 个新插件（kafka/smtp 为 stub 构建），release.yml 新增 docker job（GHCR，semver tag，GHA cache）；实际推送待 tag 触发时 CI 验证（本地无 docker daemon）。✅ schema v2→v3 升级向导——迁移前 `wal_checkpoint(TRUNCATE)` + `data.db.pre-v3.bak` 回滚点，热路径三索引（tags/subscriptions/rules），v1 老库链式迁移一步到位（persist 21/21 测试）。✅ bench 基线对比——gateway-bench `--json` 机器可读输出 + `scripts/bench_compare.py`（吞吐类按倒数分方向，阈值默认恶化 50%），nightly workflow 经 actions/cache 跨 run 传递基线，越界自动开 issue（同标题去重）。

### T5 质量纵深（M，持续）

- **目标**：长跑 soak 测试（72h+，覆盖 Lagged/重连/持久化退化）；规则/filters property tests；bench 按 README 口径自动化「3 次取中位数」对比。
- **现状差距**：测试 120+ 全绿但无 soak；bench 对比靠人工。
- **进度（2026-11-22，M3）**：✅ soak 框架就绪（`scripts/soak.sh`：sim×2 + kafka stub 北向 + flow 告警链路，周期 stop/start 重连演练，逐采样 health/发布计数/Lagged/RSS/库大小 → samples.jsonl，结束摘要含人工判据），冒烟通过（150s：采样 7 次、发布 63、告警落库 1、RSS 48→29MB 平稳、优雅停机）；**72h 首轮待启动**（CI job 上限 6h 不适合，由本机 `./scripts/soak.sh` 后台长跑）。bench 对比自动化完成（单次基线 + 阈值告警）；「3 次取中位数」与规则/filters property tests 未做（后续里程碑按需补）。

### T6 插件生态扩展（按需，每个 M）

- 候选：S7、SNMP、EtherNet/IP（南向）；OPC UA Server、SQL/WebSocket（北向）。**不在 MVP 范围**，按客户需求逐个立项（每个插件的实现路径已有成熟范式：SouthPlugin/NorthPlugin + FFI 双形态 + 真机联调）。

### T7 SaaS 化（多租户 C 形态）（XL，60+ 人日）——默认出范围
