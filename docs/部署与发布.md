# 部署与发布

> 目标读者：要把网关放到现场或服务器上的人。本文只描述**当前代码实际支持**的形态。
>
> **部署形态决策（2026-10-06 拍板）**：
> - **Linux 优先，不做 Windows 发布承诺**——运行目标为 Linux 主机（如 `letmlook@192.168.85.129`）或 Docker（compose 已提供）；Windows 仅作开发机
> - **授权维持离线软锁**（RSA 签名离线授权）；泄露过的旧密钥对已于 2026-10-06 轮换作废，现用密钥对签发
> - **验收规模：200 个设备 / 10000 个点位**——对应基准见 `docs/bench/baseline-2026-10-06-q5-scale.md`（保存 ~75 ms/次、启动加载 26.6 ms、总线端到端 ~24 万 msg/s、200 组扇出无丢弃）

## 一、构建产物

| 产物 | 来源 | 说明 |
|---|---|---|
| `gateway` | `cargo build --release -p gateway-server --bin gateway` | 网关本体（REST API + 数据面 + 静态资源托管） |
| `gateway-plugin-host` | `cargo build --release -p gateway-plugin-host` | 插件宿主进程；仅在 `GATEWAY_PLUGIN_ISOLATION=process` 时需要 |
| `libplugin_*.so`（macOS 为 `.dylib`） | `cargo build --release -p plugin-<name> --features ffi`（或 `scripts/build-plugins-so.sh`） | 可动态加载的插件 |
| `web/dist/` | `cd web && npm ci && npm run build` | 管理台静态资源 |

注意：**插件必须带 `--features ffi` 构建**才会导出 C ABI 符号。不带该 feature 的 cdylib 里没有
`gateway_south_plugin_*`，网关会跳过它并回落到内置插件（日志有 `load plugin: ...` 警告）。

## 二、直接运行

```bash
cargo build --release -p gateway-server --bin gateway
./scripts/build-plugins-so.sh            # 生成 plugins/*.so
cd web && npm ci && npm run build && cd ..

GATEWAY_PORT=3000 \
GATEWAY_DATA_DIR=./data \
GATEWAY_STATIC_DIR=./web/dist \
GATEWAY_PLUGINS_DIR=./plugins \
GATEWAY_SECRET_KEY='<强随机串>' \
GATEWAY_BACKUP_SECRET='<强随机串>' \
./target/release/gateway
```

首次启动会生成随机初始管理员口令，写入 `<data>/.admin_initial_password`（权限 0600），日志里也会打印一次：

```bash
cat data/.admin_initial_password
```

登录后请立即修改口令并删除该文件。

## 三、容器部署

```bash
docker compose up -d --build          # 网关 + mosquitto + prometheus
docker compose exec gateway cat /app/data/.admin_initial_password
```

镜像为三阶段构建：前端 → 后端（含插件）→ 运行镜像；运行镜像以非特权用户 `gateway(10001)` 启动，
只带 `gateway`、`gateway-plugin-host`、插件 `.so` 与前端静态资源。

必须持久化的是 **`/app/data`**（配置库、授权文件、节点日志）。容器探针使用免认证的
`GET /api/health`。

## 四、环境变量

### 安全（生产必设）

| 变量 | 默认 | 说明 |
|---|---|---|
| `GATEWAY_TOKEN` | 空 | 静态 API Token（等同 Admin）。设置后仍可同时用用户登录 |
| `GATEWAY_SECRET_KEY` | 空 | 敏感配置（MQTT 口令等）落盘加密密钥。**不设置则明文存储并告警** |
| `GATEWAY_BACKUP_SECRET` | 空 | 备份加密密钥；不设置则每次启动随机生成，备份换机后无法恢复 |
| `GATEWAY_ALLOWED_ORIGINS` | 空 | 允许跨域的前端来源，逗号分隔；默认不允许跨域 |
| `GATEWAY_BIND` | `0.0.0.0` | 监听地址；仅本机可用时建议 `127.0.0.1` |
| `GATEWAY_DISABLE_AUTH` | `0` | 置 1 关闭认证（**仅限本机调试**，启动会打醒目告警） |
| `GATEWAY_ENFORCE_ROLES` | `1` | 角色授权开关；置 0 可临时关闭（灰度用） |
| `GATEWAY_SESSION_TTL_SECS` | `43200` | 用户会话绝对过期秒数（自登录起算，不因活动续期，过期后请求返回 401）；置 0 恢复永不过期。静态 API Token（`GATEWAY_TOKEN`）不受影响。**升级注意**：启用 TTL 后，升级前签发的存量 token 将一次性失效，所有用户需重新登录 |
| `GATEWAY_DB_INTEGRITY` | `full` | 启动时对 `data.db` 执行完整性检查：`full` 逐行校验 / `quick` 只查结构 / `off` 完全跳过。检查失败（库损坏）时自动把坏库隔离为 `data.db.corrupt-*` 留证，并从 `data.db.bak` 恢复；无备份则空库启动（**配置丢失并打 error 日志**） |

### 路径

| 变量 | 默认 | 说明 |
|---|---|---|
| `GATEWAY_CONFIG` | `config/gateway.json` | 配置文件路径 |
| `GATEWAY_DATA_DIR` | `data` | 配置库、授权文件、队列、日志 |
| `GATEWAY_STATIC_DIR` | `web/dist` | 前端静态目录 |
| `GATEWAY_PLUGINS_DIR` | `plugins` | 插件动态库目录 |

### 规模与性能

| 变量 | 默认 | 说明 |
|---|---|---|
| `GATEWAY_BUS_CAPACITY` | `4096` | 每个分组通道的积压上限；慢消费者超限会丢包并计入 Lagged 指标 |
| `GATEWAY_MAX_CONCURRENT_POLLS` | `32` | 全局同时进行的采集次数上限（保护现场设备） |
| `GATEWAY_PERSIST_DEBOUNCE_MS` | `300` | 配置写合并窗口；置 0 退化为每次变更立即落盘 |

**data 目录单实例运行约束**：`data.db` 启动时会执行完整性检查与自动恢复，且网关以进程内单长连接访问该文件。
同一 data 目录**禁止同时运行多个网关实例**：双实例会引发锁竞争（完整性检查跳过并告警），更严重时旧实例持有已改名的坏库文件继续写入，破坏恢复语义。
扩容请按 data 目录拆分部署或使用外部负载方式，不要共享同一个目录。

### 插件

| 变量 | 默认 | 说明 |
|---|---|---|
| `GATEWAY_PLUGIN_ISOLATION` | `inproc` | `process` 时每个插件一个子进程，插件 abort/段错误不会带走网关 |
| `GATEWAY_PLUGIN_HOST_BIN` | 与网关同级 | `gateway-plugin-host` 路径 |

两种模式的取舍：

| | `inproc`（默认） | `process` |
|---|---|---|
| 单次调用开销 | 最低（一次 FFI） | 多一次进程间往返 + JSON 编解码 |
| 插件 panic | 被插件侧 `catch_unwind` 兜住 | 同左 |
| 插件 abort/段错误/死循环 | **整个网关退出** | 仅子进程退出，网关自动重启它并重放节点生命周期 |
| 适用场景 | 自研、已充分验证的插件 | 第三方或未充分验证的插件 |

## 五、数据目录

```
data/
├── data.db                     # 配置库（节点/组/点位/订阅），WAL 模式
├── data.db.bak                 # 一致性快照（每小时节流生成）
├── data.db-wal / data.db-shm   # SQLite WAL 附属文件
├── license.dat                 # 离线授权文件（未授权则不存在）
├── .admin_initial_password     # 首次启动的随机口令（登录后请删除）
└── logs/                       # 网关日志与按节点拆分的日志
```

升级与回滚：

1. 升级前 `cp data/data.db data/data.db.bak-manual`，或调用 `GET /api/export` 导出快照；
2. 替换二进制后启动；启动时会自动执行 schema 补全（不会丢旧数据）；
3. 回滚：换回旧二进制 + 恢复数据库文件即可；
4. 授权文件与机器码绑定，**换机器/换网卡后需要重新签发**。

## 八、发布流程

1. **打包**：`./scripts/package-release.sh` 一条命令完成「release 构建（网关 + 插件宿主 + 插件）→ 前端构建 → 组装 → tar.gz + SHA256SUMS」，
   产物写入 `dist/`；`SKIP_BUILD=1` 可跳过编译、只用现有 `target/release` 产物重新打包。
2. **自动发布**：推送 `v*` tag 触发 `.github/workflows/release.yml`，在 GitHub runner 上打包并创建 Release（附 SHA256SUMS）。
3. **版本信息**：`gateway-server/build.rs` 在编译时注入 `BUILD_DATE` / `GIT_REV`，`GET /api/version` 可见；包内 `VERSION` 文件记录构建元信息。
4. **CI**（`.github/workflows/ci.yml`）：`cargo check/test/clippy -D warnings/fmt --check` 全部强制，前端 `npm ci && npm run build`。
5. **性能基线**（`.github/workflows/bench-nightly.yml`）：每晚跑 `gateway-bench` 并存为构建产物，用于同机前后对比。
6. **发布前检查**：`GET /api/health` 与 `/api/metrics` 正常、默认口令已改、`GATEWAY_SECRET_KEY`/`GATEWAY_BACKUP_SECRET` 已设、授权文件在有效期内。

包内布局（不含授权文件与私钥——前者与机器码绑定，后者不能离开签发机）：

```
iot-gateway-<版本>-<os>-<arch>/
├── gateway                  # 网关本体
├── gateway-plugin-host      # 插件宿主进程（GATEWAY_PLUGIN_ISOLATION=process 需要）
├── plugins/libplugin_*.so   # 插件（--features ffi 构建）
├── web-dist/                # 管理台静态资源（GATEWAY_STATIC_DIR 指向这里）
├── config/                  # 默认配置
├── deploy/                  # Prometheus 抓取配置与告警规则
├── VERSION                  # 版本与构建元信息
└── README.md
```
