# 南向设备与北向应用业务逻辑梳理

## 一、数据流概览

```
南向设备(轮询) ──GroupData──► Bus(广播) ──过滤──► 北向应用(订阅) ──► 云/MQTT/HTTP
```

- **南向**：按 Group 定时轮询采集 Tag，将 `GroupData { node_id, group_id, ts, values }` 发布到 Bus
- **北向**：订阅 Bus，按 `SubscriptionTable` 过滤，对匹配的 GroupData 调用 `on_group_data` 转发

---

## 二、南向设备业务逻辑

### 2.1 生命周期

| 阶段 | 调用 | 说明 |
|------|------|------|
| 创建 | `open` → `init` | 创建节点时；open 建立连接/状态，init 初始化全局资源 |
| 启动 | `start` | 用户点击启动；准备 poll_group / write_tags |
| 运行 | `poll_group` 循环 | 按 Group.interval_ms 定时采集，结果 publish 到 Bus |
| 停止 | `stop` | 用户点击停止；取消轮询任务 |
| 配置变更 | `setting` | 修改插件配置；若在运行则自动重启轮询使新配置生效 |
| 删除 | `uninit` → `close` | 释放资源；删除时同步清理北向订阅中对该节点的引用 |

### 2.2 组与标签

- **组 (Group)**：南向专有；`interval_ms` 控制轮询间隔；同节点下组名唯一
- **标签 (Tag)**：南向专有；归属某组；同组内标签名唯一；支持 `validate_tag` 校验
- **首次启动**：若 Store 中无组，从插件 `list_groups` / `list_tags` 同步默认组和标签

### 2.3 关键点

- 南向修改配置（host/port 等）后，若节点在运行，Manager 会自动 stop → setting → start，使新配置生效
- 南向无组时不会产生任何轮询任务，即不会向 Bus 发布数据
- 删除南向节点时，会清理所有北向订阅中引用该 `south_node_id` 的项

---

## 三、北向应用业务逻辑

### 3.1 生命周期

| 阶段 | 调用 | 说明 |
|------|------|------|
| 创建 | `open` → `init` | 创建节点时；如 MQTT 创建客户端、连接 Broker |
| 启动 | `start` → `set_subscriptions` | 用户点击启动；订阅 Bus，按订阅表过滤后调用 on_group_data |
| 运行 | `on_group_data` | 收到匹配的 GroupData 时；如 MQTT 发布到主题 |
| 停止 | `stop` | 用户点击停止；取消 Bus 消费任务 |
| 配置变更 | `setting` | 修改插件配置；如 MQTT 的 close+open 重连 |
| 删除 | `uninit` → `close` | 释放资源 |

### 3.2 订阅管理

- **订阅表**：`SubscriptionTable`：北向 node_id → `[(south_node_id, group_id), ...]`
- **设置订阅**：会过滤无效项（south_node_id 或 group_id 不存在）；若北向在运行则自动重启消费任务使新订阅生效
- **删除南向组时**：自动清理所有北向订阅中对该 `(south_node_id, group_id)` 的引用

### 3.3 关键点

- 北向**必须先添加订阅**才能收到数据；订阅可在运行中动态增删，无需重启节点
- 北向无订阅时，Bus 消费任务仍运行，但不会向插件传递任何 GroupData
- MQTT 等有外部连接的北向，通过 `connection_status` 暴露实际连接状态

---

## 四、持久化与恢复

### 4.1 持久化内容

- 节点（id、name、kind、plugin_name、config、**state**）
- 组（南向）
- 标签（南向）
- 北向订阅表

### 4.2 启动加载 (apply_snapshot)

- 清空 Store，填入快照
- **所有节点 state 重置为 Stopped**（确保与运行时一致）
- 对每个节点调用 `open`、`init`
- 用户需手动启动南向和北向节点

---

## 五、已实现与待扩展

### 5.1 已实现

| 能力 | 说明 |
|------|------|
| 南向轮询 | 按 Group.interval_ms 定时 poll_group，publish 到 Bus |
| 北向订阅过滤 | Bus 消费按 (south_node_id, group_id) 过滤 |
| 订阅热更新 | 运行中修改订阅时自动重启消费任务 |
| 南向配置热更新 | 运行中修改配置时自动重启轮询任务 |
| 订阅引用清理 | 删除南向节点/组时自动清理北向订阅中的无效引用 |
| 订阅校验 | set_subscriptions 时过滤不存在的 south/group |
| 加载后状态一致 | apply_snapshot 后所有节点置为 Stopped |

### 5.2 可选扩展

- 南向组 `interval_ms` 变更后需重启南向节点才能生效（当前 Store 更新了值，但运行中任务用的是启动时快照）
- 南向 `poll_group` 持续失败时，可将节点 state 设为 Error（当前仅打日志）
- 北向除 MQTT 外（HTTP、Kafka 等）按 NorthPlugin 实现即可

---

## 六、典型使用流程

1. **创建南向设备**（如 sim、modbus-tcp）→ 配置连接参数
2. **启动南向** → 若有默认组则自动同步；若无则需手动添加组和标签
3. **创建北向应用**（如 MQTT）→ 配置 Broker 等
4. **添加订阅** → 选择南向节点和组
5. **启动北向** → 开始接收并转发数据

数据流：南向轮询 → Bus → 北向过滤 → on_group_data → MQTT 发布
