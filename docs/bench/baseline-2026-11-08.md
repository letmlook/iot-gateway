## 解读

- 总线：合作式发布 200,000 条、丢弃 0 条（每 32 条让出一次仍可能被调度抖动顶到容量上限）；容量 64 + 慢消费者时丢弃 43,699 条 —— 这是 Lagged 的预期语义，生产环境应通过 `gateway_north_lagged_by_node` 告警，而不是期望「不丢」。
- 以上为**单次运行**结果。绝对值随机器与后台负载波动明显（本机重复运行的差异可达 2 倍），因此只应用于「同机同负载下改造前后对比」，并建议各跑 3 次取中位数。
- 持久化保存曾是最大瓶颈（5000 点位约 83 ms/次）：`save_to_db` 对每一行都重新 prepare 语句，删除差集还会拼出约 10 KB 的 `NOT IN (...)`。已用 `prepare_cached` + 临时键表修掉，同机复测降到约 13 ms/次（见 baseline-2026-09-26-persist-fix.md）。
- **机器变更说明（重要）**：本文件为**首份 Linux 机器基线**（x86_64，72 核，rustc 1.99.1，与 Q2「Linux 优先」决策的运行目标一致）。此前所有基线（2026-09-26 / 2026-10-06 / 2026-10-06-q5-scale）均产自 Windows 开发机，**数值与本文件不可横向比较**；自本文件起，后续 Linux 复测与本文件同机对比。本基线覆盖了缺陷①~⑤修复批（2026-10-07）与深度 Code Review 批（2026-10-25，含持久化 `persist_lock` 串行化、级联删除等 24 项修复）之后的代码形态，作为该形态在 Linux 上的参照点。
