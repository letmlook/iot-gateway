# 多租户：决策方案（待拍板）

> 结论先行：**多租户不是技术问题，是交付形态问题。** 在明确「这套网关是否要以 SaaS/托管方式卖给多个互不可见的客户」之前，
> 不应开始实现——它决定了数据模型、认证模型与运维模型，做错的返工成本远高于晚做。

---

## 一、现状（单租户）

| 维度 | 现状 |
|---|---|
| 部署 | 一站点一套网关（单机或单容器），数据落在本机 `data/` |
| 隔离 | 无租户概念：全部节点/组/点位/规则/历史属于同一个实例 |
| 认证 | 单实例内的用户体系（Admin/Operator/Viewer）+ 可选静态 Token |
| 授权 | 按角色（功能级），**不按数据范围**：任何 Operator 都能操作全部设备 |
| 历史 | `history.db` 按点位名存储，无租户维度 |

对「一套网关服务一个车间/产线」的交付形态，这是**正确且够用**的设计。

---

## 二、三种可选形态

### 形态 A：保持单租户（现状）

- **适用**：私有化单站交付、边缘盒子。
- **代价**：0。
- **风险**：若客户后来要求「一套系统看多个厂区且互相不可见」，只能靠部署多实例 + 外部聚合，届时需要另做聚合层。

### 形态 B：单实例 + 数据域隔离（"软多租户"）

一套实例内引入「域（tenant/project）」维度，**同一实例内按域隔离设备与数据可见范围**。

- **适用**：一套网关服务多个班组/车间/区域，或客户希望在同一管理台里划分责任范围。
- **最小实现清单**（按依赖顺序）：

  | 步骤 | 内容 | 影响面 |
  |---|---|---|
  | B1 | `users` 表加 `tenant_id`；登录会话携带域 | `users/store.rs`、认证中间件 |
  | B2 | 节点/组/点位/规则/订阅的键上带 `tenant_id`（或不带，但访问时按域过滤） | `store.rs`、`persist.rs`（表结构 + 快照版本升级） |
  | B3 | 中间件注入 `AuthContext.tenant`，所有查询强制按域过滤（**默认拒绝跨域**） | `api/mod.rs` + 每个 handler |
  | B4 | 历史库加 `tenant_id` 列 + 复合索引 | `history.rs` |
  | B5 | 北向订阅、规则动作、离线队列按域隔离（避免 A 域规则写 B 域设备） | 插件配置、规则引擎 |
  | B6 | 审计：谁在哪个域做了什么 | 新增审计表 |

- **代价**：约 **15–25 人日**（含回归测试与数据迁移），且**必须同时重构持久化 schema 与快照版本**（现有 `data.db` 需要迁移）。
- **风险**：
  - 漏一个查询条件就是跨租户数据泄露 —— 必须用「默认拒绝 + 集中式过滤」而不是逐个 handler 记得加条件；
  - 设备侧无隔离：同一台 PLC 被两个域引用时，"隔离"只是逻辑上的，物理操作仍会互相影响。

### 形态 C：多租户 SaaS

- 每租户独立实例或独立库 + 配额 + 计费 + 自助开通/注销。
- **适用**：以订阅方式对外售卖。
- **代价**：**60+ 人日**起步（控制面、租户生命周期、配额、计费、跨租户运维、安全合规），且需要独立的产品与商业模式。
- **风险**：在没有明确的商业化路线前投入，几乎必然返工。

---

## 三、建议

1. **没有 SaaS 交付诉求时：保持形态 A**，把精力放在已完成的可靠性与功能补齐上（规则引擎、历史、离线队列、进程隔离）。
2. **有「一套实例多域」诉求时：做形态 B**，但先明确三个问题：
   - 域之间是**可见性隔离**还是**强隔离**（前者允许管理员跨域查看）？
   - 同一台设备会被多个域引用吗？（若是，需要定义冲突策略）
   - 历史数据按域删除/导出是否必须？
3. **形态 C 单独立项**，且必须先有：计费口径、SLA、租户注销后的数据处理策略。

---

## 四、需要拍板的问题

| # | 问题 | 影响 |
|---|---|---|
| Q1 | 是否存在「一套系统服务多个互不可见的客户/组织」的交付诉求？ | 决定是否启动形态 B/C |
| Q2 | 若有，是可见性隔离还是强隔离？ | 决定过滤放在 API 层还是存储层 |
| Q3 | 设备是否会被多域共享？ | 决定是否需要设备归属表与冲突策略 |
| Q4 | 是否需要按域做配额（点数/节点数/历史容量）？ | 决定是否引入配额模型（形态 C 必备） |

> 建议先回答 Q1。若答案为「否」，本议题可以关闭并在 `docs/功能实现清单.md` 中标注为"不做（当前交付形态不需要）"。
